## 1. 추진 배경과 현안

- 지게차 소음 · 진동 시험은 엔진 회전수(RPM)를 바꿔 가며 여러 위치(소음 Mic · 진동 가속도계)의 주파수 스펙트럼을 잽니다. 어느 RPM 에서 어느 오더(회전 차수)가 커지는지, 전체(Overall) 중 몇 %를 차지하는지 봐야 대책을 정할 수 있습니다.
- 제출자는 Testlab Neo 에서 내보낸 CSV 를 브라우저에서 바로 분석하는 도구를 직접 만들어 왔습니다(v34 → v40 → v51).
- 이번 요청은 기능이 아니라 **첫 화면의 인상**입니다 — 이 도구가 무엇을 하는지(지게차 · 소음 진동 · 오더) 열자마자 보이게 하는 것.

## 4. 기능 — 제출자 분석기 v51 (있는 그대로)

코드를 읽고 헤드리스 브라우저로 직접 돌려 확인한 내용입니다.

### 4.1 CSV 올리기 · 인식 확인

- 끌어 놓기 또는 「CSV 파일 선택」. 파일은 서버로 보내지 않고 브라우저 안에서만 읽음.
- 글자 인코딩 자동 판단(UTF-8 → CP949/EUC-KR).
- Curve 마다 메타데이터(Run name · Dataset name · Point id · Point direction · DOF id · X/Y 축 단위 · label)에서 RPM · 위치 · 방향 · 소음/진동 구분(Pa 또는 dB 이면 소음)을 뽑음.
- 인식 신호등(초록 · 노랑 · 빨강)과 Curve 표(RPM · 채널 · 위치 · 방향 · 단위 · 데이터 수 · 주파수 범위 · 상태)를 보여 주고, 오류가 없을 때만 「분석 실행」이 켜짐.

### 4.2 Order Analysis

- 채널 선택(소음 · 진동 묶음, 전체 · 해제), 오더 입력(쉼표로 여러 개), 피크 검색 범위 ±Hz, 피크 중심 합산 범위 ±Hz.
- 계산: 1X = RPM ÷ 60, N차 = N × RPM ÷ 60, 이론 주파수 ± 검색 범위 안의 최대 Bin 을 시험 피크로, 피크 ± 합산 범위의 에너지를 오더 진폭으로.
- 그래프(가로 RPM): 오더별 진폭, 오더 RSS 합산(2개 이상일 때), Overall(전체 스펙트럼 에너지) — 표시 켜고 끄기, 축 최소 · 최대, 그래프 높이 끌어 조절, 요약 칸(선택 채널 · 오더 · 계열 수 · 최대 Order 진폭).
- 단위: 소음 · 진동 따로 Amplitude / dB / dBA, dB 기준값(소음 2e-5 Pa, 진동 1.0197e-7), CSV 가 dB 로 들어오면 Raw 기준값으로 선형 환산. dBA 는 A-weighting 식.

### 4.3 차수별 기여도 분석 (v40 요청 → v51 에 제출자가 넣음)

- RPM 마다 기여도(%) = Aᵢ² ÷ Overall² × 100. 요약(Overall 최대 · 평균 최대 기여 차수 · 최대 기여도 · 발생 RPM · 유효 RPM 수), 차트, 표.
- 오더 2개 이상, 그리고 **모든 RPM 에서 모든 선택 오더의 진폭이 있어야** 계산합니다(하나라도 없으면 「유효 데이터 없음」). 예시 CSV 는 1,000~1,800 Hz 만 있어 오더 30 · 36 · 42 를 넣으면 5개 RPM 모두 나옵니다.

### 4.4 Spectrum Map

- 채널 하나를 골라 가로 주파수(또는 오더) × 세로 RPM 컬러맵, 오더 성분 선 겹치기, 축 · 색 범위 조절, 마우스를 올리면 값, 최대값 위치 표시.

### 4.5 XLSX 저장 · 기타

- 「Order Analysis XLSX 저장」 — 라이브러리 없이 직접 만든 엑셀 파일: Settings · Order Analysis · Order RSS Sum(오더 2개 이상) · Order Contribution(기여도가 있을 때) 시트.
- 다크 모드(브라우저에 기억), 옛 검증 화면(파일 요약 · 구조 검증 · 매핑 · Curve 목록 · 정규화 JSON · 최근접 Bin · 옛 컬러맵 · 경고)은 코드와 화면 요소가 남아 있고 숨겨져 있음.

### 4.6 돌려 보며 본 것 (원본 v51 과 이 리포가 똑같이 보임)

- 가상 예시 CSV 2개로 원본 v51 과 이 리포를 같은 순서로 조작해 요약 · 범례 · 기여도 · Spectrum Map 최대값 · 그래프 픽셀 합을 비교 — **모두 같음**.
- 분석한 뒤 **채널 이름이 다른 CSV 를 이어서 열면** 콘솔 오류 1건(`script.js` 1079줄 `renderMultiAnalysis` — 이전 파일의 채널 선택이 남아 `channelType` 을 못 읽음). 원본 v51 에서도 똑같이 나고, 새 파일의 화면은 정상으로 그려집니다. 고칠지는 10장에서 여쭙니다.

## 5. 첫 화면(히어로) 설계 — 이번에 더한 것

| 부분 | 내용 |
|---|---|
| 자리 | 머리글(Order Analysis · v51 · 다크모드 버튼) 바로 아래, 머리글과 같은 남색 그라데이션 안. 다크 모드 색도 머리글을 따라감 |
| 왼쪽 글 | 「지게차 소음 · 진동 오더 분석」, 한 줄 설명, 3단계(CSV 올리기 → 인식 확인 · 분석 실행 → 그래프 · XLSX), 「CSV 파일 선택」(도구의 파일 입력을 그대로 엶) · 「예시 CSV 받기」 |
| 오른쪽 그림 | 캔버스: 가상 캠벨 선도 — 가로 Frequency (Hz) 0~250, 세로 RPM 800~2,800, 12단 색 띠 + 띠 경계선(등고선), 오더 선 1 · 2 · 4 · 6차(점선 · 이름표), 구조 공진 48 · 118 · 196 Hz. 색은 도구 Spectrum Map 과 같은 색 띠 |
| 섞기 | 왼쪽에 지게차 SVG, 그 뒤로 엔진 둘레 소음 등고선(같은 색 띠), 엔진의 가속도 센서 → 그래프로 점선 케이블 |
| 움직임 | RPM 커서가 오르내리며 오더 선과 만나는 점 · 읽음표(「RPM 1,440 · 가장 큰 성분 2차 48.0 Hz」)를 보여 줌. 그 진폭만큼 지게차가 떨리고 센서 물결이 커짐 |
| 멈춤 | 「동작 줄이기」(prefers-reduced-motion) → 2,350 RPM 멈춘 그림. 탭 숨김 · 화면 밖(IntersectionObserver) → 그리기 멈춤 |
| 정직한 표기 | 그림 아래 「가상의 캠벨 선도 — 실제 시험값이 아닙니다」 |
| 파일 | `css/hero.css`(색 토큰 `:root`), `js/hero.js`(계산은 순수 함수 — node 테스트) |

가상 스펙트럼 식(`js/hero.js`): A(RPM, f) = 바닥 소음(RPM 이 오르고 주파수가 낮을수록 조금 큼) + Σ 오더 진폭 × exp(−((f − N·RPM/60)/3.2)²) + 공진 띠. 오더 진폭 = 기본값(2차 1.0 · 4차 0.45 · 1차 0.35 · 6차 0.22 — 4기통 엔진은 2차가 폭발 차수라고 가정) × RPM 비례 × 공진 배율(1 + Σ gain · exp(−((f − f₀)/bw)²)).
